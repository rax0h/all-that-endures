# Next integration boundary

Start from the repaired runtime, the immutable map contract, and the green source receipts. This is a handoff, not permission to replace current integrity checks with node hashes alone.

1. Exact content preimages are now implemented in `persistence_proof_content.py` (see the transition-input spec/results). The closed retained-version adapter now authenticates actual fetched bytes and exact interval selection (`persistence_proof_version.py`; see `../proof-version-results.md`). It requires external expected authority and returns raw bytes only. Accepted manifests, reference/topology checks and canonical admission remain prerequisites. Ordinary `records` overwrite payloads today: define retained immutable payload availability before treating old manifests as readable. SQL row presence is not authority.
2. The ordered-relation primitive now authenticates complete bounded pages and local predecessor/successor transitions (`persistence_proof_order.py`, `persistence_proof_order_edit.py`). The closed physical query adapter now checks real pinned query rows against mandatory expected certificates without owner-payload reads (`persistence_proof_query.py`; see `../proof-query-results.md`). It returns raw metadata only and has no production certificate constructor or World selection. Before adoption, supply accepted manifest authority and a separately budgeted certificate-checked path for encoded keys above4096 bytes. The closed owner/group occurrence adapter authenticates actual bounded placement pages with explicit ordered source indexes (`persistence_proof_occurrence.py`; see `../proof-occurrence-results.md`). General old-pin selection when newer rows intervene, plus large-field paths, remains gated. Next specify complete owner/group/link adapters and cross-consistency; preserve reference projections, owner/group/link cross-consistency, retirement/absence and allocator bounds. This primitive alone does not provide complete World topology or authenticate SQL interval selection. Exclusions apply after verified raw pages. Positive membership alone still does not prove a complete ordered query.
3. Specify generation manifests and retained-root authority. Bind store identity, generation/parent, rules/codec/format, allocator/counter state, content/topology/query/event roots and the existing exact commit token/recovery receipt. Define root reachability for head, pins, unresolved acknowledgement and protected checkpoints before any node collection. The new `update_sorted` helper reuses shared changed paths and persists final nodes only; callers still need a bounded sorted-delta staging path in actual publication.
4. Implement explicit verified-copy construction outside ordinary open/save. Retain the checked old-format reader; fence old writers before allowing any upgraded file to use proof authority. Do not advertise a new format capability until all mandatory root contracts exist.
5. Integrate changed data and successor roots through `LazyRecordStore.commit` and the existing frozen participant protocol in `persistence_lazy_participants.py`. Validate actual changed-row/root bindings and exercise `before_head`, `before_commit`, `after_commit`, lost acknowledgement, rollback, stale pins and external writes. Never add a second authoritative sidecar/publisher.
6. Consume the accepted roots in save and open. Preserve canonical action/alias identity before exposing objects; include first interaction in latency measurements. Keep full logical audit and bounded physical scrub. Prove the real World point-edit save reads zero unrelated historical payloads at 1k/10k/100k archive sizes, then measure matched mature phases and exact fresh recovery.

Existing source seams: `persistence_lazy_store.py` prepares and atomically writes version/ordinary/segment changes and resolves exact commit attempts. `persistence_lazy_participants.py` freezes actual changed sources and catalog witnesses. `persistence_catalog_copy.py` owns checked-copy construction. Reuse those authorities rather than introducing a competing generation or canonical-object registry.

No World format activation or save/open bypass is implemented in this primitive branch. The transition-input plan covers only batch merge and pure content bindings. The next World-integration implementation plan must still resolve the remaining contracts explicitly; do not silently fill a missing root with a success flag.
