# Native value-only World transitions

Existing lazy World record updates can reuse the accepted semantic facts when their
complete reference projection is unchanged. The producer authenticates actual old
bytes, field/target kinds, query projections, singleton inline identity groups, source
witness revisions and backing lease updates. Publication independently requires unchanged
complete structural scopes, allocator, collection directory, record cardinality and
namespace inventory/counts. Changed ordinary counters retain exact envelopes and their
head binding. No caller supplies an `already_validated` flag.

Native preparation and acknowledgement borrow a connection-owned SQL capability which
blocks unlisted durable writes. Only the existing proof publisher and explicit full audits
receive write windows. Window boundaries reinstall authorizers so cached prepared writes
cannot escape, and caller authorizers/read-only fault callbacks remain effective. The capability starts before
the entry epoch check; nested SQL from trace, progress or authorizer callbacks is rejected,
including writes through a previously prepared cursor. The
accepted native successor and exact epoch are checked inside a locked metadata transaction;
external writes or schema changes are rejected rather than adopted by a new epoch sample.
Thus a proved value-only save avoids the previous three full World audits. No-op unchanged
epochs remain unchanged; uncertain recovery retains the full audit and original receipt.

The measured domain is existing lazy registered record values excluding Event bodies,
with unchanged reference paths/kinds/targets. A changed inline identity requires a proven
singleton group. Source/body limits are512 changed rows and4MiB aggregate bytes for this
fast classification. Additions/deletions, structural/backing edits, shared inline identity
changes, new layout/allocator/identity authority or larger batches retain explicit full
audit. These are supported checked fallbacks, not silently certified fast transitions.
Shared referenced histories remain cold when their references do not change.

The explicit native opener still performs full import/admission audit and existing
canonical restoration; recovery is still expensive. Default format7 admission remains
blocked. This package does not claim fast open, unrestricted year-step saves, total memory
bounds or matched mature-world performance. The previous closed-session error-type Minor
remains deferred; no main merge, automatic migration or endurance run occurs here.

The native-value scaling driver measures actual first lazy record access, assignment,
frozen preparation, existing-writer save and complete native acknowledgement at1k/10k/100k
retained history values. It prohibits full audit during the measured save and counts
unrelated history-body reads. Admission/construction are reported separately. A separate
fresh-session save uses an interval-one SQLite VM guard; a third fresh-session save records
unprofiled first-access latency. Final reopen checks exact values
and canonical shared-history identity. Retained values are not mature World record counts
or simulation years. Final measurements, source hashes and reviewer rulings are retained
in value-transition/ after verification.
