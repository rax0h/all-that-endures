# Retained ordinary content and atomic record-root publication

Implement the ordinary-content availability prerequisite from the approved proof architecture. Existing `records` overwrites remain unchanged for default callers. An explicit full-verified bootstrap copies exact current ordinary bodies into an immutable content-addressed table and constructs the existing record-content preimage map. A bounded raw reader uses mandatory external expected certificate authority, exact live current/previous pin and actual retained bytes. It returns bytes/schema/revision or authenticated absence, never World objects or topology authority.

Selected approach: retain exact ordinary bodies and publish successor record roots in the existing `LazyRecordStore.commit` SQLite transaction. Reusing overwritten records cannot support old roots; a second commit/publisher would break recovery. Root construction/full audit is explicit archive work. Ordinary proof updates follow actual prepared changed records and shared proof paths; no unrelated old payload reads. Use SQLite staging for sorted deltas, existing proof nodes and commit token/receipt protocol.

Add a private optional commit request plus explicit wrapper; all default callers unchanged. Derive roots from actual prepared bytes and compare actual written changed rows after `before_commit`, immediately before `_commit_sqlite`. Revalidate accepted parent row in the locked transaction. Root, immutable bodies, head, ordinary rows and existing receipt either commit together or roll back. No-op/conflict returns do not fabricate successor roots. Lost acknowledgement resolves the existing exact token and binds the recovered root row to parent commitment, pin token and encoded commit token; never replay changes. Recovery returns a checked local publication result, not an independently protected external checkpoint.

Body reads default1MiB (explicit maximum64MiB), metadata default1MiB (maximum64MiB); ordinary construction probes locator bytes, fixed checksum bytes, source classes and revision0..head before full audit; guard SQL classes and lengths before transfer. Bootstrap and proof-aware writes support ordinary bodies up to64MiB; larger values require a separately budgeted checked path. No caller codec hooks. Arbitrary transactions rejected. No collector or implicit ancestor traversal.

This is one content-root producer/consumer. Remaining topology/target/inventory/query/order/event root construction, complete atomic manifest publication, writer fencing/format capability and canonical World admission remain gated. A default/old writer may advance without record proofs; the next proof-aware operation must fail closed on the missing current root and require an explicit fully verified reconstruction. No format capability is advertised and no World reader selects these tables. Root hashing/retention alone is not complete World authority.

Proof-aware phase hooks run with a connection-owned read-only SQL authorizer, chained to and restoring any caller authorizer. Transaction control, writes and callback guard removal are denied before execution. Default hooks stay unchanged. Native connection replacement/private Python monkeypatching is not a security boundary.
