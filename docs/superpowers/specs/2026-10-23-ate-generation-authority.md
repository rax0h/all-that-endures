# Inactive generation manifest binding

Continue the approved October21 proof architecture. Use existing SQLite, immutable proof primitives and exact existing pin receipts. No new registry, publisher, format capability, World reader bypass or node collector.

The next deliverable is a closed binary manifest plus bounded raw source reader, successor binding and pure retention-root inventory. Alternatives: trusting self-reported database roots is insufficient; wiring World paths before manifests and complete topology would violate existing gates. Author decision: implement the inactive binding now, then integrate complete verified construction and atomic publication separately. The user's existing instruction to continue autonomously covers this bounded step.

Manifest fields: store identity; generation and exact parent generation/commitment; physical format, codec, simulation schema and rules identity; incarnation allocator; exact raw head fields simulation_position, next_ids, namespace_inventory, namespace_counts and seed; seven named Root slots (versions, records, topology, queries, orders, events, inventory); and the existing writer pin/encoded commit token/committed receipt checksum. Generation0 has no parent or receipt. Positive generations require both. Canonical length-framed binary encoding, strict types (including bool rejection), bounded fields and aggregate encoded size<=2MiB. Root slots are commitments requiring complete verified producers, never missing-root success markers. This step establishes bindings, not semantic validity of supplied component roots.

Mandatory external expected digest for decoding/source reads. A manifest stored with its own digest is not independent authority. The reader shares one checked live pin snapshot, only current/previous generation, checks actual bounded bytes and source context. Current generation compares exact physical head blobs/seed; old head blobs rely on externally accepted manifest because the old save_head row is unavailable. Both compare retained allocator and fixed store metadata. Current available exact writer receipt must agree; historical overwritten/released receipt availability is not invented. Private head preflight rejects native restoration/hooks. No owner, archive or event payload bodies.

Successor validation binds exact expected parent digest, adjacent generation, unchanged store/format/codec/schema/rules, monotone allocator, exact supplied encoded commit token and existing receipt checksum. It does not validate changed payload/root preimages, game time/RNG transitions or perform publication. Those remain atomic writer obligations.

Retention inventory takes externally checked manifest pairs explicitly protected by head, pins, unresolved parent/successor acknowledgements and checkpoints. It deduplicates root references and manifests, rejects conflicting generation manifests, bounds protection entries and never collects bytes. Protecting roots does not make old overwritten bodies readable. No implicit unbounded ancestor walk.
